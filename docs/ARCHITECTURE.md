# speech 0.2.0 架构

## 运行链路

```text
浏览器文字/录音
    → assistant（鉴权、输入检查、网页与 API）
        → speech（本地 ASR/TTS）
        → sub2api / OpenAI 兼容模型接口
    ← 回答文字与合成音频
```

Compose 项目名为 `speech`，使用同一镜像启动两个服务：

- `assistant`：监听容器端口 8000，默认映射到 NAS 的 18080；提供浏览器页面、文字问答，并转发语音请求。
- `speech`：监听容器内网端口 8001，加载镜像内置的 SenseVoiceSmall INT8 与 MeloTTS ONNX 模型，不发布 NAS 主机端口。

内部语音服务使用独立令牌；未显式设置 `SPEECH_TOKEN` 时，由 `APP_TOKEN` 派生。外部与内部请求均有输入限制。容器使用非 root 用户、只读根文件系统和临时 `/tmp`。

## 对话和模型

`POST /v1/chat` 通过服务端配置的 OpenAI 兼容模型生成回答。支持 Responses、Chat Completions，以及消费上游 SSE；设备 API 按轮返回完整 JSON。模型地址和密钥不会发到浏览器。

浏览器在当前页面内存维护最近 10 轮完整问答，每次随请求发送。刷新或新建对话会清空；服务端没有持久会话数据库，也没有长期记忆。

语音识别和合成独立于大模型：未配置模型时仍可使用。模型问答也不依赖 speech 服务的可用性。各接口的限制、鉴权和错误行为见 [API.md](../API.md)。

## 部署和版本

NAS 运行时只需一个 Compose 和一个 `.env`。0.2.0 的 Compose 固定版本，镜像包含语音模型，不需要模型初始化服务或主机模型目录。旧目录可保留用于回退。

源码端 `make release` 负责构建、真实容器检查及镜像上传。Git 源码发布与镜像发布分别管理；NAS 更新是独立操作，具体步骤见 [DEPLOY.md](../DEPLOY.md)。

## 尚未交付

天猫精灵 APK、官方语音技能适配、持续流式语音、打断、唤醒词和长期记忆都不是 0.2.0 的已实现功能。将设备接入本服务需要独立验证其录音、播放或官方平台能力。
